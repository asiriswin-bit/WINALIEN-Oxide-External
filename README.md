## Исправление ESP для x86_64 в 0.2.7

В 0.2.6 сборщик был x86_64, но использовал профиль игры ARM64. Из-за этого ESP не получал данных: журнал показывал `build_mismatch`. Добавлен профиль самой игры x86_64 с соответствующими build ID и адресами TypeInfo. Поля объектов и нативные пути Transform/Camera сверены по x86_64-дампу и коду Unity.

Исправлены передача flags в process_vm_readv на x86_64 и выбор загруженного образа библиотеки при наличии обычной копии файла в памяти. Настройки, касания и скрытие меню сохранены.

12 автоматических проверок проходят. Проверены фактические файлы x86_64-библиотек, три TypeInfo, поля 11 классов и инструкции чтения координат/камеры. **Отображение ESP 0.2.7 на MSI ещё требует проверки**: подключённого ADB-устройства нет. Меню и скрытие подтверждены пользователем ранее.

Для обновления останови старый external, запусти новый EXE, нажми «Скачать файлы», затем «Старт external». Если остался старый процесс, перезапусти эмулятор перед запуском новой версии.

Если в заголовке осталось `0.2.5`, закрой лоадер и замени `OxideLoader.exe` по ссылке выше. Исправленный EXE показывает `0.2.7` в интерфейсе и свойствах файла, а архитектуру игры — `x86_64`. Кнопка «Скачать файлы» обновляет runtime и ADB, но не сам EXE.

## Где находится меню

Игровое меню и ESP рисует **Android-бинарник внутри эмулятора** через SurfaceControl + EGL/OpenGL ES 3. Лоадер на Windows использует ImGui/DX11 для загрузки файлов и запуска через ADB. Отдельного игрового окна Windows больше нет.

Меню перенесено по образцу предоставленного WINALIENPRO1protection/Overlay: исходные шрифты Poppins, значки, логотип, перетаскиваемая панель вкладок и карточки с настройками через шестерёнки.

## Запуск

1. Сохрани новый EXE в отдельную папку.
2. Запусти Android-эмулятор x86_64 с ADB и игрой Oxide 11924 x86_64. Бинарнику нужны права UID 0 внутри эмулятора; в BlueStacks лоадер использует встроенный `/system/xbin/bstk/su`.
3. В лоадере укажи ADB-порт и нажми «Старт external». Файлы скачиваются из этого релиза с проверкой размера и SHA-256.
4. Нажми «Открыть Oxide». Меню должно появиться внутри эмулятора; оно открывается сразу при старте бинарника.
5. **Insert** — открыть/закрыть меню, **F6** — ESP. При закрытом меню в эмуляторе остаётся **watermark справа сверху**; нажатие на него открывает меню.
6. Настройки ESP и радара находятся в игровом меню. `Config` сохраняет `/data/local/tmp/oxide-settings.cfg`; есть автосохранение.
7. Останови external кнопкой в лоадере. Закрытие EXE само по себе не завершает Android-бинарник.

Ключ активации не нужен. Windows-окно эмулятора выбирать больше не требуется. Комплект использует протокол 2: обнови и EXE, и бинарник.

## Возможности и проверка

ESP по категориям, имена, числовое HP, расстояния, рамки трёх стилей, заливка, линии, стрелки за экраном, фильтры, цвета и оформление текста. Радар с размером, дальностью, подписями и положением. Статический прицел.

**Aim, Silent, AutoFarm, Visible Check, Skeleton, Chams и Skins пока не реализованы.** Обход античита не заявляется.

Собраны Windows, ARM64 и x86_64. Двенадцать автоматических проверок и тестовый рендер меню при 1010×680/1515×1020 пройдены. Проверены клики, ползунок, прокрутка, темы, закрытие, открытие через watermark и перенос панели вкладок. Скрин выше — рендер интерфейса, не снимок из игры. Совпадение ESP с игрой ещё требует проверки на устройстве.

Обёртка native-поверхности рассчитана на Android 9–15 и использует внутренний libgui. Совместимость конкретной прошивки не гарантирована. При `overlay_unavailable` сохрани журнал из лоадера; там указана ошибка libgui/EGL.
